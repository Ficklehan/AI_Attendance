Processing Logic

核心处理逻辑分解

从文件上传到飞书落库，按阶段拆解关键组件、API 与数据落点。

任务状态机

processing 识别中 → processed 待核对 → confirmed 已确认 → synced 已同步飞书
failed 识别失败 · cancelled 已作废 · sync_failed 同步失败可重试
1

客户端选择文件

支持 JPG / PNG / PDF。PC 端图片自动压缩；PDF 原文件上传，服务端按页转 JPEG（最高 30 页，200 DPI）。

// PC 多图：首张 deferRecognition，其余 append，最后触发 recognize submitBackgroundRecognition(files) → POST /local/upload-async startTaskRecognition(taskId) → POST /local/tasks/{id}/recognize
2

校验与归一化

ImageUploadValidator 校验文件头；UploadMediaSupport 将 PDF 展开为多页 ImagePage；保存至 uploads/ 并写入 tasks.image_urls。

3

创建任务

TaskService.createTask 生成 task_id（日期流水），状态 processing，快照 prompt_country 供后续识别与飞书映射。

1

识别编排 RecognitionRunner

按国家加载提示词（recognition_prompt 表优先）；多页 PDF/多图依次识别，合并 raw_data JSON 数组；识别进度周期性刷入 DB 供轮询。

2

MiMo 流式调用 AIParserService

构造 vision message（text prompt + image_url base64）；流式解析 JSON Lines 员工记录；length 截断时自动续写（最多 5 轮）。

// 质量守卫 RecognitionPromptGuard · RecognitionQualityGuard // 拒绝表头 echo、编造数据、不可读时间
3

识别完成

写入 tasks.raw_data，状态 → processed；anomaly_summary 记录风险与跟踪链；引擎标记如 mimo:FR。

1

待核对（processed）

PC / 小程序可编辑字段、删除行、标记异常。小程序「修改」在确认前写回内存草稿，与 confirm 一并提交。

2

确认提交 POST /tasks/{id}/confirm

RecordConfirmValidator 校验必填字段；写入 confirmed_data；附加 TASK_ID、UPLOADED_BY；状态 → confirmed。

3

已确认后校准（recordCalibrate）

仅 confirmed 状态；写回 _calibrationHistory、_manualCalibrated；SmartMark 展示「人工校准」标签；异步触发单条飞书更新。

1

FeishuSyncService 异步同步

按 prompt_country 读取 base-config/feishu.md 字段映射；BitableService.batchWriteRecordsReturningIds 批量写入。

2

回写飞书记录 ID

合并 _feishuRecordId 至 confirmed_data；sync_status → synced 或 sync_failed（可重试）。

3

导出与审计

ExportJobService 异步生成 Excel；audit_logs 记录登录、配置变更与敏感操作。

AI Recognition

识别引擎与多端策略

PC 与小程序采用不同上传模式，共享同一识别内核与任务状态。

PC · 后台识别 + 轮询

  • 单图：upload-async 后立即异步识别
  • 多图：批量上传后 /tasks/{id}/recognize 合并
  • 前端 pollRecognitionUntilDone 拉取 partial raw_data
  • 离开页面后可通过 localStorage 恢复进度

小程序 · 异步上传 + 轮询

  • recognitionUpload.js 封装全流程
  • 多图任务同样走 recognize 合并接口
  • RecognitionTrace 全链路日志供排查
  • 识别页独立展示引擎与国家配置

提示词按国家

  • 运行时数据源：recognition_prompt 表
  • 编辑源：base-config/prompts.md
  • 启动播种：PromptDatabaseBootstrap
  • 内置 canonical 模板 + seed_version 版本控制

识别记录字段（示例）

  • NO · Pays · Entrepot · Date · NOM_PRENOM
  • ARRIVEE · DEPAR · PAUSE · SmartMark
  • Observations · SIGNATURE · AGENCE_INTERIMAIRE
Data Model

数据模型与一致性

任务统计的单一事实来源为 GET /tasks/summary，禁止用分页列表长度代替全库计数。

表 / 存储核心字段说明
tasks task_id, status, raw_data, confirmed_data, image_urls, sync_status, prompt_country 识别任务主表；JSON 存员工行数组
users username, feishu_user_id, role PC 密码登录 + 飞书绑定共享任务
recognition_prompt country_code, ai_prompt, continue_prompt, user_modified 各国 AI 提示词运行时配置
export_jobs export_type, status, file_path, dismissed_at 异步导出任务与下载文件
audit_logs action, target_type, details 操作审计追溯

summary 接口字段

  • processing — 识别中
  • review — 待核对（processed）
  • confirmed — 已完成
  • allUsersScope — 管理员全员视图

数据范围

  • 普通用户：仅本人 user_id 任务
  • 管理员：全部用户任务 + 导出同范围
  • TaskAccessService 统一鉴权
Security & Config

安全、权限与配置分层

敏感配置与环境分离；功能权限由 JSON 驱动，管理员保留校准等特权。

Layer 1 · 环境变量 / .env DB_* · JWT_SECRET · FEISHU_* · MIMO_API_KEY
Layer 2 · application.yml attendance.prompt.* · export.* · 框架开关
Layer 3 · base-config/ feishu.md · prompts.md · permissions.json
Layer 4 · MySQL 运行时态 tasks · recognition_prompt · export_jobs

Deployment

部署与启动

本地开发与公网部署双轨；启动自举确保表结构与提示词就绪。

本地开发

  • mysql < backend/config/init.sql
  • ./start.sh all → 后端 :8080 + 前端 :5175
  • API 基址 /attendance/api
  • 默认账号 admin / admin123（仅 dev）

启动自举（Java）

  • ExportJobDatabaseBootstrap @Order(15)
  • PromptDatabaseBootstrap @Order(20)
  • DefaultAdminBootstrap（dev profile）

公网 / 生产

  • deploy/environments/production.yaml
  • npm run render:deploy:all 渲染 env
  • 飞书开放平台配置回调与合法域名
  • 小程序 USE_PUBLIC_API=true

仓库结构

  • backend/ Spring Boot + MyBatis
  • frontend/ Vue 3 PC
  • feishu-miniprogram/ 小程序
  • base-config/ · docs/ · deploy/
