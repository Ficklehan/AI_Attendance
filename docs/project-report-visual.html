概览

一句话总结

考勤数据宁可空不可编；不确定就标出来，让人来决定。
📸
拍照即采集
现场纸质/电子考勤表拍照上传，AI 自动逐格 OCR 识别，支持多语言表头与手写混排。
✓
异常优先核对
系统自动标记模糊、疑似、缺失行，人工只需聚焦 10% 异常，正常行抽样确认即可。
⇄
一键入账飞书
确认后自动结构化写入飞书多维表格，支持按国别映射字段、失败重试与审计追踪。
业务篇

我们在解决什么问题

跨国仓储、劳务外包场景下，考勤数据的人工入账成本高、错误率高、多端协同断裂。

📋
表单形态多样
纸质拍照、多语言表头（中/法/德/荷/西等）、手写与打印混排，格式不统一。
⏱
人工入账成本高
现场拍完照，后台需逐行抄写姓名、日期、到离时间、休息、签字等到飞书多维表格。
⚠
AI 不可盲信
大模型容易「猜时间」「抄示例」「把表头当数据」，直接入库会造成合规与对账风险。
🔗
多端协同断裂
现场用手机、办公室用 PC，若任务与统计不一致，核对效率反而下降。

不是
「全自动无人值守考勤系统」
而是
「AI 辅助 + 人工把关 + 飞书落地」的人机协同录入平台

现场拍照识别
飞书小程序 · 移动端
选择国家 → 拍照/相册 → 识别进度 → 结果页 → 抽样核对 → 确认提交

02
办公室深度核对
PC Web · 桌面端
任务列表 → 任务详情 → 表格编辑 → 异常分组 → 确认提交 → 同步状态
◆ PC 承担高密度信息：多列同屏、批量浏览、配置中心
◆ 重复名检测、格式高亮、必填缺失分组展示
03
确认后校准
已入账修正 · 审计链
◆ 具备 recordCalibrate 权限的用户可对单行做校准
◆ 修改字段 + 必填原因，写入审计链
◆ 异步更新飞书对应行，承认「确认不是终点」
04
运营提醒
待核对滞后 · 闭环驱动
◆ 对长期停留在 processed 的任务，按可配置规则发送通知
◆ PC 站内通知（铃铛）+ 飞书交互卡片
◆ 提醒是闭环，不是骚扰：周期桶去重、全局开关

提效思考与价值

效率杠杆不在「取消人工」，而在缩小注意力范围、下沉重复劳动、一键化入账动作。

从「抄表」到「审表」

传统方式AttendanceAgent 方式
✕ 人眼读图 + 手敲每一格 ✓ AI 逐格 OCR + 人只处理异常
✕ 错误发现靠对账 ✓ 识别阶段即打标：模糊/手写/未出勤/夜班
✕ 多国表各自一套 Excel ✓ 一国一提示词 + 一国一飞书映射，配置驱动
✕ 手机拍了发微信，PC 再录 ✓ 小程序拍照 → 同账号任务 PC 可续审
🔍
缩小注意力范围
只看异常行、异常字段，正常行抽样提交即可
⚙
重复劳动下沉机器
格式归一、夜班重算、重复名比对全部自动化
⇄
入账动作一键化
确认即 structured JSON → Bitable 批量写入

校验与规则设计

校验不是「卡用户」，而是把风险前置到确认按钮之前，让操作者始终知道「为什么不能提交」以及「改哪里」。

L1
识别层质量守卫
AI 产出后、展示前 — 示例行过滤 / 表头占位过滤 / 臆测时间检测 / 图片可读性评估
L2
展示层异常聚合
结果页 / 任务编辑页 — 标记列翻译 / 必填缺失 / 看不清字段 / 重名疑似 / 格式异常
L3
确认提交阻断
客户端预检 + 服务端强校验 — 必填项 / 字段格式 / 到离相同 / 删除 & 未出勤豁免
L4
同步层
确认之后 — 已删除行不写飞书 / 按国开关同步 / 失败可重试不 rollback
✓
必填校验（可配置）
默认必填：姓名、日期、到达、离开、休息。管理员可配置，整行豁免已删除/未出勤行，占位符视为缺失。
⊞
格式校验（固定开启）
日期 YYYY-MM-DD、班次须含两个时间、到达/离开各为一个时间点、到达=离开则禁止确认。
⊕
识别语义校验 SmartMark
AI 输出标记列：正常、模糊、手写、夜班、未出勤、已删除。后端与前端统一翻译为可读标签。
≡
重复名 & 夜班规则
按国家+仓库+日期+中介+基础姓名分组检测重复。夜班支持全局默认+按国覆盖，不仅依赖模型自报。

核心数据流

识别入库
POST /local/upload-stream (SSE) → 创建 task (processing) → AIParserService 流式调用 MiMo → 行级 JSON 解析 + 归一化 → RecognitionQualityGuard 质量判定 → 写入 raw_data / task_records → status = processed | failed
确认与同步
POST /tasks/:id/confirm → ConfirmValidationService 校验 → 清洗字段 → confirmed_data → TaskRecordSyncService 同步员工宽表 → 取消提醒调度 → 异步 FeishuSyncService → Bitable → sync_status: pending → synced | sync_failed
所有端「待核对 N 条」「任务 Tab 角标」必须来自 GET /attendance/api/tasks/summary，禁止用列表分页 records.length 冒充全库统计。
