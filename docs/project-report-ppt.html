背景

我们在解决什么问题

跨国仓储、劳务外包场景下，考勤数据的人工入账面临五类核心问题。

📋
表单形态多样
纸质拍照、多语言表头（中/法/德/荷/西等）、手写与打印混排，格式不统一。
⏱
人工入账成本高
后台需逐行抄写姓名、日期、到离时间、休息、签字等到飞书多维表格。
⚠
AI 不可盲信
大模型容易猜时间、抄示例、把表头当数据，直接入库有合规风险。
🔗
多端协同断裂
现场用手机、办公室用 PC，若任务与统计不一致，核对效率反而下降。
🌍
跨国规则差异
不同国家的飞书表结构、字段映射、夜班判定、提示词语义均不同。
定位

产品定位与核心原则

我们做的不是全自动系统，而是人机协同的录入平台。

不是
「全自动无人值守考勤系统」
而是
「AI 辅助 + 人工把关 + 飞书落地」的人机协同录入平台
考勤数据宁可空不可编；不确定就标出来，让人来决定。

核心流程

任务状态机

把「AI 产出」与「业务入账」明确切开——只有 processed → confirmed 才代表业务承诺。

上传 / 识别processing
→
待核对processed · 人工主战场
→
已确认confirmed
→
飞书写入synced / sync_failed
failed 识别失败   cancelled 作废
设计意图
识别阶段的一切都可回退、可改、可作废。只有确认提交这一步才产生业务承诺，之后的飞书同步失败也不回滚确认。
单一事实源
所有端「待核对 N 条」必须来自 GET /tasks/summary，禁止用列表分页冒充全库统计——这是多端一致性的硬约定。

校验

四层校验模型

校验不是卡用户，而是把风险前置到确认按钮之前。每次阻断都告诉用户改哪里、为什么。

L1
识别层 · 质量守卫
AI 产出后、展示前 — 示例行过滤 / 表头占位过滤 / 臆测时间检测 / 图片可读性评估
L2
展示层 · 异常聚合
结果页 / 编辑页 — 标记翻译 / 必填缺失标红 / 看不清字段 / 重名 / 格式黄标
L3
确认提交 · 阻断
客户端预检 + 服务端强校验 — 必填项 / 字段格式 / 到离相同 → 禁止确认
L4
同步层 · 过滤
确认后 — 已删除行不写飞书 / 未出勤不同步工时 / 失败可重试
活人严格、死人放宽
已删除行、未出勤行豁免必填，不逼迫给缺勤行编时间。占位符（???、-、n/a）视为缺失。
失败可解释、可定位
弹窗按字段分组 + 行号区间聚合。PC 自动滚动到首个问题单元格并闪动 2.2 秒。
校验 · L1

识别层：什么情况下整单不过

宁可整单失败，也不让假数据进核对表。模型产出必须值得让人花时间核对。

场景系统判定用户看到
图片过糊Laplacian 方差 < 80 → 上传前即拒绝提示重拍，不消耗识别配额
示例行被抄进结果PromptGuard 剥示例 + 命中 ≥3 条 → 整单拒绝「含多条提示词示例行，请换照片」
图糊但时间整齐≥60% 行姓名不可辨 + ≥50% 行有整齐到离 → 拒绝「疑似臆测，请换更清晰照片」
表头被当数据行姓名命中表头词 + 多字段像表头 → 该行丢弃通常少一行脏数据，用户无感
整表可读性不达标模糊行 ≥50% 或关键格 ??? ≥65% → 阻断任务 failed 或结果页黄条警告
对账阶段最怕「看起来完整其实是编的」。L1 直接挡在核对之前，不让假数据浪费人工时间。

AI 管线

提示词：让 AI 老老实实读表

模型被定位为逐格读图的 OCR 提取器，不是考勤助手。提示词的第一职责是约束行为，第二才是提高召回。

可读性三态
看清 / ??? / ""，绝不猜测
先结构后填格
定位表头 → 数行 → 逐格 → 自检
15 列固定 schema
多国表头不同，入账结构统一
标记列承载语义
告诉核对者这行要不要细看
十条禁止推断
点名模型常犯的脑补场景
删线行仍输出
已删除=true，审计可追溯
示例必须剥掉
运营需要示例做对照，但发给模型的示例必须剥掉，否则模型把「张三 + 中介A + 08:00」当标准答案。命中 ≥3 条则整单拒绝。
夜班从提示词拿掉
夜班边界是可配置业务规则（各国不同），不应写死在 prompt 里让模型各自理解。由系统 NightShiftMarkSupport 重算。
