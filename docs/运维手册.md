# AI 考勤智能助手 — 运维手册

> 适用版本：AttendanceAgent（Spring Boot 2.7 + Vue3 + 飞书小程序）  
> 当前公网域名配置源：`deploy/environments/production.yaml`  
> 最后更新：2026-06

---

## 1. 系统概述

| 组件 | 技术 | 默认端口/路径 |
|------|------|----------------|
| 后端 API | Spring Boot 2.7 | `8080`，上下文 `/attendance/api` |
| PC 前端 | Vue3 + Vite | 开发 `5175`；生产由 Nginx 托管静态资源 |
| 飞书小程序 | 原生小程序 | 通过 HTTPS 调用后端 API |
| 数据库 | MySQL 8.0 | 库名 `attendance_assistant` |
| AI 识图 | MiMo Vision API | 外网 `api.xiaomimimo.com` |

**配置分层原则**

| 层级 | 位置 | 内容 |
|------|------|------|
| 公网域名 / 回调 URL | `deploy/environments/production.yaml` | **唯一人工维护的域名来源** |
| 密钥 / 数据库 | `deploy/secrets.env` | 不进 Git |
| 业务配置 | `base-config/` | 飞书多维表映射、权限、提示词源 |
| 运行时数据 | MySQL、`uploads/`、`exports/` | 任务、用户、导出文件 |

## 4. 首次部署（生产服务器）

### 4.1 拉取代码

```bash
cd /opt
git clone <仓库地址> AttendanceAgent
cd AttendanceAgent
```

### 4.2 初始化数据库

```bash
mysql -u root -p < backend/config/init.sql
```

已有旧库升级见 [backend/config/README.md](../backend/config/README.md)。

### 4.3 配置密钥

```bash
cp deploy/secrets.example deploy/secrets.env
chmod 600 deploy/secrets.env
vim deploy/secrets.env
```

**必填项**

| 变量 | 说明 |
|------|------|
| `DB_HOST` / `DB_USER` / `DB_PASSWORD` | MySQL 连接 |
| `JWT_SECRET` | 至少 **32 字节**随机字符串 |
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | 飞书应用凭证 |
| `MIMO_API_KEY` | 小米 MiMo 识图 API |

**不要在 `secrets.env` 里写生产域名或飞书回调 URL**（由 render 从 `production.yaml` 生成）。

### 4.4 配置公网域名

编辑 `deploy/environments/production.yaml`：

```yaml
public:
  host: uat-guanpei.eminxing.com   # 改成你的域名
  scheme: https
```

### 4.5 配置 Nginx（示例）

```nginx
server {
    listen 443 ssl;
    server_name uat-guanpei.eminxing.com;

    # ssl_certificate ...

    # 后端 API
    location /attendance/api/ {
        proxy_pass http://127.0.0.1:8080/attendance/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 20m;
    }

    # PC 前端静态资源（先 npm run build）
    location / {
        root /opt/AttendanceAgent/frontend/dist;
        try_files $uri $uri/ /index.html;
    }
}
```

### 4.6 构建 PC 前端（可选）

```bash
cd frontend
npm install
npm run build
# 产物在 frontend/dist/
```

### 4.7 启动后端

```bash
cd /opt/AttendanceAgent
./start.sh prod
# 或前台调试：
# bash scripts/start-backend-prod.sh
```

启动过程会自动：

1. 执行 `render-deploy-config.mjs` 生成 `deploy/rendered/production.env`
2. 加载 `deploy/secrets.env` + rendered env
3. 以 `prod` profile 启动 Spring Boot

### 4.8 飞书开放平台

登录 [飞书开放平台](https://open.feishu.cn)，应用 ID：`cli_a96dfac04b789cbb`（以实际为准）。

启动后查看生成的回调地址：

```bash
grep FEISHU_ deploy/rendered/production.env
```

在平台配置：

| 配置项 | 值来源 |
|--------|--------|
| 重定向 URL | `FEISHU_REDIRECT_URI` |
| 小程序 request 合法域名 | `PUBLIC_HOST`（不含 `https://`） |

### 4.9 部署飞书小程序

1. `feishu-miniprogram/config.js` 设置 `USE_PUBLIC_API = true`
2. 执行 `./start.sh restart-prod`（确保 `config.prod.js` 已生成）
3. 飞书开发者工具上传并发布

### 4.10 验收

```bash
# 飞书凭证
curl -s "https://uat-guanpei.eminxing.com/attendance/api/feishu-auth/readiness" | jq .

# 期望: code=200, data.feishuConfigured=true

# PC 前端
curl -s -o /dev/null -w "%{http_code}\n" "https://uat-guanpei.eminxing.com/"
```

## 5. 日常运维

### 5.1 命令速查

| 操作 | 命令 |
|------|------|
| 本地开发（前后端） | `./start.sh all` |
| 生产首次/启动后端 | `./start.sh prod` |
| **改域名后重启** | `./start.sh restart-prod` |
| 仅渲染配置（少见） | `./start.sh render-deploy` |
| npm 等价重启 | `npm run restart:prod` |
| UAT 环境重启 | `ATTENDANCE_DEPLOY_ENV=uat ./scripts/restart-backend-prod.sh` |

### 5.2 改域名（核心流程）

```bash
# 1. 只改一处
vim deploy/environments/production.yaml

# 2. 重启（自动 render，无需手跑 render 命令）
./start.sh restart-prod

# 3. 飞书开放平台同步改重定向 URL 和合法域名

# 4. 小程序重新上传飞书开发者工具
```

### 5.3 停止服务

```bash
# 查找占用 8080 的进程
lsof -ti :8080 | xargs kill

# 或使用 systemd
sudo systemctl stop attendance-backend
```

### 5.4 使用 systemd（推荐生产）

`/etc/systemd/system/attendance-backend.service`：

```ini
[Unit]
Description=AttendanceAgent Backend
After=network.target mysql.service

[Service]
Type=simple
User=deploy
WorkingDirectory=/opt/AttendanceAgent
Environment=ATTENDANCE_DEPLOY_ENV=production
ExecStart=/opt/AttendanceAgent/scripts/start-backend-prod.sh
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable attendance-backend
sudo systemctl start attendance-backend
sudo systemctl status attendance-backend
```

**改域名后**：`sudo systemctl restart attendance-backend`（启动脚本会重新 render）。

### 5.5 环境变量加载顺序

```
deploy/secrets.env（或 backend/.env）
    ↓
deploy/rendered/production.env   ← 覆盖 URL、域名、CORS、SPRING_PROFILES_ACTIVE
```

### 5.6 性能表 `task_records`（B+）

后端启动时会自动：

1. 创建 `task_records` 行级表（见 `backend/config/migration/007_task_records.sql`）
2. 对尚无行级数据的历史任务做一次性回填（日志关键字：`task_records 历史回填完成`）

**日常无需手工跑 SQL。** 识别完成、确认、校准、作废、失败及飞书 `record_id` 回写后会自动同步。

| 现象 | 处理 |
|------|------|
| 考勤记录列表为空但任务详情有数据 | 等待回填完成，或 `./start.sh restart-prod` 触发再次回填 |
| 回填较慢 | 任务量大时首次启动多等 1～2 分钟，看后端日志 |
| 单用户识别报 429 | 同账号并发识别超过 `attendance.recognition.max-per-user`（默认 2），稍后再试 |

可选：手动执行迁移 SQL（与自动建表结构一致）：

```bash
mysql -u root -p attendance_assistant < backend/config/migration/007_task_records.sql
mysql -u root -p attendance_assistant < backend/config/migration/008_task_progress.sql
```

### 5.7 性能终局（Phase 2，已内置）

| 能力 | 说明 |
|------|------|
| `GET /tasks/{id}/progress` | 识别轮询只拉 status/行数/引擎，不拉整段 JSON |
| 识别进度写库 | 平时只更新 `progress_row_count`；每 20 条才写一次全量 `raw_data` |
| 重名检测 | baseline 按当前页 `work_date` + `base_name` 收窄，最多 5000 行 |
| `task_records` | 按 `row_key` upsert + 删除孤儿行，不再全表 delete+insert |
| 慢 SQL / 慢接口 | 日志阈值见 `attendance.performance.*` |
| 对象存储 | `attendance.storage.type=oss` + `OSS_*` 环境变量；默认 `local` |

OSS 生产示例（`deploy/secrets.env` 或环境变量）：

```bash
ATTENDANCE_STORAGE_TYPE=oss
OSS_ENDPOINT=https://oss-cn-hangzhou.aliyuncs.com
OSS_BUCKET=your-bucket
OSS_ACCESS_KEY_ID=...
OSS_ACCESS_KEY_SECRET=...
OSS_KEY_PREFIX=attendance/
OSS_PUBLIC_BASE_URL=https://cdn.example.com/attendance/
```

## 6. 配置说明

### 6.1 production.yaml 字段

| 字段 | 说明 | 示例 |
|------|------|------|
| `public.host` | 公网域名（无协议） | `uat-guanpei.eminxing.com` |
| `public.scheme` | 协议 | `https` |
| `paths.api_context` | API 根路径 | `/attendance/api` |
| `paths.feishu_oauth_callback` | OAuth 回调路径段 | `/feishu-auth/callback` |
| `paths.frontend_feishu_callback` | PC 飞书登录成功页 | `/feishu/callback` |
| `spring.profile` | Spring profile | `prod` |

render 后自动推导：

| 变量 | 示例 |
|------|------|
| `PUBLIC_BASE_URL` | `https://uat-guanpei.eminxing.com/attendance/api` |
| `FEISHU_REDIRECT_URI` | `https://.../attendance/api/feishu-auth/callback` |
| `FEISHU_FRONTEND_CALLBACK_URL` | `https://.../feishu/callback` |
| `CORS_ALLOWED_ORIGIN` | `https://uat-guanpei.eminxing.com` |

### 6.2 Spring Profile

| Profile | 用途 | 配置文件 |
|---------|------|----------|
| `dev` | 本地开发 | `application-dev.yml` |
| `prod` | 生产 | `application-prod.yml` + `application-deploy.yml` |
| `uat` | UAT（同域不同连接池/日志） | `application-uat.yml` + `application-deploy.yml` |

生产安全开关（`application-deploy.yml`）：

- `bootstrap-default-admin: false`
- `allow-public-registration: false`
- `allow-simulated-recognition: false`

## 8. 故障排查

### 8.1 后端启动失败

| 错误信息 | 原因 | 处理 |
|----------|------|------|
| `FEISHU_REDIRECT_URI 未设置` | 未走 `start-backend-prod.sh` 或未 render | 使用 `./start.sh restart-prod` |
| `生产环境必须配置 JWT_SECRET` | secrets 缺失或太短 | 检查 `deploy/secrets.env` |
| `Port 8080 was already in use` | 旧进程未退出 | `lsof -ti :8080 \| xargs kill -9` |
| 数据库连接失败 | MySQL 未启动或密码错误 | 检查 `DB_*` 变量 |

### 8.2 飞书登录失败

| 现象 | 排查 |
|------|------|
| PC 飞书登录 500 | 服务器能否访问 `open.feishu.cn`：`curl -I https://open.feishu.cn` |
| 小程序「凭证未配置」 | `readiness` 接口 + `FEISHU_APP_SECRET` |
| 小程序 network error | 是否 `USE_PUBLIC_API=true`；合法域名是否配置 |
| OAuth 回调 404 | Nginx 是否转发 `/attendance/api`；`FEISHU_REDIRECT_URI` 是否与平台一致 |

详细步骤见 [飞书小程序登录问题排查.md](../飞书小程序登录问题排查.md)。

### 8.3 改域名后仍访问旧地址

1. 确认已改 `production.yaml` 而非其他文件
2. 执行 `./start.sh restart-prod`（不是只 kill 再 mvn）
3. 检查 `deploy/rendered/production.env` 中 `PUBLIC_HOST` 是否已更新
4. 飞书开放平台、小程序是否已同步
