# AI 考勤智能助手 — 运维手册

> 适用版本：AttendanceAgent（Spring Boot 2.7 + Vue3 + 飞书小程序）  
> 当前公网域名配置源：`deploy/environments/production.yaml`  
> 最后更新：2026-06

---

## 1. 系统概述

| 组件 | 技术 | 默认端口/路径 |
|------|------|----------------|
| 后端 API | Spring Boot 2.7 | `8080`，上下文 `/attendance/api` |
| PC 前端 | Vue3 + Vite | 开发 `5175`；生产由 Nginx 托管静态资源 |
| 飞书小程序 | 原生小程序 | 通过 HTTPS 调用后端 API |
| 数据库 | MySQL 8.0 | 库名 `attendance_assistant` |
| AI 识图 | MiMo Vision API | 外网 `api.xiaomimimo.com` |

**配置分层原则**

| 层级 | 位置 | 内容 |
|------|------|------|
| 公网域名 / 回调 URL | `deploy/environments/production.yaml` | **唯一人工维护的域名来源** |
| 密钥 / 数据库 | `deploy/secrets.env` | 不进 Git |
| 业务配置 | `base-config/` | 飞书多维表映射、权限、提示词源 |
| 运行时数据 | MySQL、`uploads/`、`exports/` | 任务、用户、导出文件 |

## 4. 首次部署（生产服务器）

### 4.1 拉取代码

```bash
cd /opt
git clone <仓库地址> AttendanceAgent
cd AttendanceAgent
```

### 4.2 初始化数据库

```bash
mysql -u root -p < backend/config/init.sql
```

已有旧库升级见 [backend/config/README.md](../backend/config/README.md)。

### 4.3 配置密钥

```bash
cp deploy/secrets.example deploy/secrets.env
chmod 600 deploy/secrets.env
vim deploy/secrets.env
```

**必填项**

| 变量 | 说明 |
|------|------|
| `DB_HOST` / `DB_USER` / `DB_PASSWORD` | MySQL 连接 |
| `JWT_SECRET` | 至少 **32 字节**随机字符串 |
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | 飞书应用凭证 |
| `MIMO_API_KEY` | 小米 MiMo 识图 API |

**不要在 `secrets.env` 里写生产域名或飞书回调 URL**（由 render 从 `production.yaml` 生成）。

### 4.4 配置公网域名

编辑 `deploy/environments/production.yaml`：

```yaml
public:
  host: uat-guanpei.eminxing.com   # 改成你的域名
  scheme: https
```

### 4.5 配置 Nginx（示例）

```nginx
server {
    listen 443 ssl;
    server_name uat-guanpei.eminxing.com;

    # ssl_certificate ...

    # 后端 API
    location /attendance/api/ {
        proxy_pass http://127.0.0.1:8080/attendance/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 20m;
    }

    # PC 前端（Vite base=/attendance/，先 npm run build）
    location /attendance/ {
        alias /opt/AttendanceAgent/frontend/dist/;
        try_files $uri $uri/ /attendance/index.html;
    }
}
```

### 4.6 构建 PC 前端（可选）

```bash
cd frontend
npm install
npm run build
# 产物在 frontend/dist/
```

### 4.7 启动后端

```bash
cd /opt/AttendanceAgent
./start.sh prod
# 或前台调试：
# bash scripts/start-backend-prod.sh
```

启动过程会自动：

1. 执行 `render-deploy-config.mjs` 生成 `deploy/rendered/production.env`
2. 加载 `deploy/secrets.env` + rendered env
3. 以 `prod` profile 启动 Spring Boot

### 4.8 飞书开放平台（概要）

小程序与 PC 飞书登录均依赖开放平台配置。**逐项清单与操作顺序见 [§5.8 飞书小程序生产配置](#58-飞书小程序生产配置完整流程)。**

启动后端后，用 render 产物核对要在平台填写的值：

```bash
grep -E '^(PUBLIC_HOST|PUBLIC_BASE_URL|FEISHU_)=' deploy/rendered/production.env
```

### 4.9 部署飞书小程序（概要）

生产小程序需完成：**代码开关 → 生成 config.prod.js → 后端生产启动 → 开放平台域名 → 开发者工具上传发布**。完整步骤见 [§5.8](#58-飞书小程序生产配置完整流程)。

### 4.10 验收

```bash
# 飞书凭证
curl -s "https://uat-guanpei.eminxing.com/attendance/api/feishu-auth/readiness" | jq .

# 期望: code=200, data.feishuConfigured=true

# PC 前端
curl -s -o /dev/null -w "%{http_code}\n" "https://uat-guanpei.eminxing.com/"
```

## 5. 日常运维

### 5.1 命令速查

| 操作 | 命令 |
|------|------|
| 本地开发（前后端） | `./start.sh all` |
| 本地仅后端（推荐） | `./start.sh dev` |
| 生产首次/启动后端 | `./start.sh prod` |
| **改域名后重启** | `./start.sh restart-prod` |
| 仅渲染配置（少见） | `./start.sh render-deploy` |
| npm 等价 | `npm run start:dev` / `npm run restart:prod` |
| UAT 环境重启 | `ATTENDANCE_DEPLOY_ENV=uat ./scripts/restart-backend-prod.sh` |

### 5.2 改域名（核心流程）

```bash
# 1. 只改一处
vim deploy/environments/production.yaml

# 2. 重启（自动 render，无需手跑 render 命令）
./start.sh restart-prod

# 3. 飞书开放平台同步改重定向 URL 和合法域名

# 4. 小程序重新上传飞书开发者工具（见 §5.8 阶段 E）
```

### 5.8 飞书小程序生产配置（完整流程）

> **适用场景**：手机飞书客户端、体验版/正式版访问公网 API（当前示例域名：`uat-guanpei.eminxing.com`）。  
> **不适用**：本机开发者工具 + `localhost`（见 [§5.8.8 本地与生产对照](#588-本地开发与生产对照)）。

#### 5.8.0 配置项总览（逐项勾选）

| 序号 | 配置项 | 在哪里配 | 生产示例 / 说明 |
|------|--------|----------|-----------------|
| A1 | 公网域名 | `deploy/environments/production.yaml` → `public.host` | `uat-guanpei.eminxing.com` |
| A2 | HTTPS / Nginx | 服务器 Nginx | 将 `/attendance/api/` 反代到 `127.0.0.1:8080` |
| B1 | 数据库连接 | `deploy/secrets.env` | `DB_HOST` / `DB_USER` / `DB_PASSWORD` |
| B2 | JWT 密钥 | `deploy/secrets.env` | `JWT_SECRET`（≥32 字节） |
| B3 | 飞书应用 ID | `deploy/secrets.env` | `FEISHU_APP_ID`（与小程序 AppID 一致） |
| B4 | 飞书应用密钥 | `deploy/secrets.env` | `FEISHU_APP_SECRET` |
| B5 | MiMo API | `deploy/secrets.env` | `MIMO_API_KEY` |
| C1 | 使用公网 API | `feishu-miniprogram/config.js` | `USE_PUBLIC_API = true` |
| C2 | 公网 API 基址 | 自动生成 `feishu-miniprogram/config.prod.js` | `https://uat-guanpei.eminxing.com/attendance/api` |
| C3 | 小程序 AppID | 飞书开发者工具「项目配置」 | 与 `FEISHU_APP_ID` 相同 |
| D1 | request 合法域名 | 飞书开放平台 → 开发配置 → 服务器域名 | 只填主机名：`uat-guanpei.eminxing.com` |
| D2 | 重定向 URL（PC OAuth） | 飞书开放平台 → 安全设置 | 与 `FEISHU_REDIRECT_URI` 完全一致 |
| E1 | 上传/发布小程序 | 飞书开发者工具 | 改 C1/C2 或改域名后**必须重新上传** |
| E2 | 真机校验合法域名 | 开发者工具 → 本地设置 | **取消**「不校验合法域名…」 |

**不要在 `deploy/secrets.env` 里写** `PUBLIC_*`、`FEISHU_REDIRECT_URI` 等 URL（由 render 从 `production.yaml` 生成，避免与平台不一致）。

#### 5.8.1 阶段 A：服务器与域名（先于小程序）

**步骤 A-1** — 确认 `production.yaml` 域名正确：

```yaml
# deploy/environments/production.yaml
public:
  host: uat-guanpei.eminxing.com
  scheme: https
```

**步骤 A-2** — Nginx（或网关）已配置：

- [ ] `https://<PUBLIC_HOST>/attendance/api/` → 后端 `http://127.0.0.1:8080/attendance/api/`
- [ ] `client_max_body_size` ≥ 20m（上传考勤图）
- [ ] 响应头含 `X-Forwarded-Proto: https`（OAuth 回调依赖）

**步骤 A-3** — 公网可访问 API（未起后端前可能失败，起后端后再验）：

```bash
curl -s -o /dev/null -w "%{http_code}\n" \
  "https://uat-guanpei.eminxing.com/attendance/api/config/current-country"
# 期望: 200
```

#### 5.8.3 阶段 C：小程序工程内配置

| 步骤 | 文件 / 操作 | 配置什么 | 生产应设为 |
|------|-------------|----------|------------|
| C-1 | `feishu-miniprogram/config.js` | 是否走公网 | `const USE_PUBLIC_API = true` |
| C-2 | 执行 render | 生成 `config.prod.js` | 见下方命令 |
| C-3 | 确认 `config.prod.js` 存在 | API 根路径 | `PUBLIC_BASE_URL=https://…/attendance/api` |
| C-4 | 飞书开发者工具 | 项目 AppID | 与 `FEISHU_APP_ID` 一致 |
| C-5 | 清除调试覆盖（如有） | 本地 Storage | 见下方说明 |

**C-2 生成 config.prod.js**（服务器上 `restart-prod` 已包含；本地打包上传前可手跑）：

```bash
node scripts/render-deploy-config.mjs --env production
# 生成: feishu-miniprogram/config.prod.js（gitignore，勿提交）
```

**C-5 清除 apiBaseUrlOverride**（曾在控制台用公网/内网穿透调试时）：

- 小程序启动时若 `USE_PUBLIC_API=false`，会自动清除非 localhost 的覆盖；
- 或调试器执行：`tt.removeStorageSync('apiBaseUrlOverride')`

**提交 Git 时注意**：只提交 `config.js`（`USE_PUBLIC_API=true`）；**不要**提交 `config.prod.js`（由 render 生成）。

#### 5.8.4 阶段 D：飞书开放平台（逐项）

登录 [飞书开放平台](https://open.feishu.cn) → 进入与 `FEISHU_APP_ID` 对应的应用。

先在本机查看要填写的精确字符串：

```bash
grep -E '^(PUBLIC_HOST|FEISHU_REDIRECT_URI)=' deploy/rendered/production.env
```

| 步骤 | 平台菜单位置 | 填什么 | 常见错误 |
|------|--------------|--------|----------|
| D-1 | 开发配置 → 开发信息 → App ID | 与 `FEISHU_APP_ID`、开发者工具一致 | AppID 抄错导致登录失败 |
| D-2 | 开发配置 → 服务器域名 → **request 合法域名** | `PUBLIC_HOST` 的值，**无** `https://`、**无**路径 | 写成 `https://uat-guanpei...` 或带 `/attendance` |
| D-3 | 安全设置 → **重定向 URL** | `FEISHU_REDIRECT_URI` 全路径 | 少 `/attendance/api` 段；http 与 https 混用 |
| D-4 | （可选）安全设置 → IP 白名单 | 若启用，需包含服务器出口 IP | 未加 IP 导致服务端调飞书 API 失败 |

**说明**：

- 小程序登录接口：`POST {PUBLIC_BASE_URL}/feishu-auth/miniprogram/login`，**不经过浏览器重定向**，但 **D-2 合法域名必须配置**，否则真机报 `network error`。
- **D-3** 主要给 **PC 网页** 飞书扫码登录；与小程序登录共用同一应用凭证。

当前示例（以 render 为准）：

| 配置项 | 值 |
|--------|-----|
| request 合法域名 | `uat-guanpei.eminxing.com` |
| 重定向 URL（PC OAuth） | `https://uat-guanpei.eminxing.com/attendance/api/feishu-auth/callback` |
| PC 登录成功页（非开放平台项，后端跳转用） | `https://uat-guanpei.eminxing.com/attendance/feishu/callback` |

#### 5.8.7 改域名后的同步顺序

```text
1. 修改 deploy/environments/production.yaml → public.host
2. 服务器执行 ./start.sh restart-prod
3. 本地/CI 执行 node scripts/render-deploy-config.mjs --env production
4. 飞书开放平台：改 D-2 合法域名、D-3 重定向 URL
5. 确认 config.js 仍为 USE_PUBLIC_API=true
6. 飞书开发者工具重新上传并发布小程序
7. 按 §5.8.6 复测 F-1～F-5
```

#### 5.8.8 本地开发与生产对照

| 项目 | 本地开发 | 生产 |
|------|----------|------|
| `USE_PUBLIC_API` | `false` | `true` |
| API 地址 | `http://localhost:8080/attendance/api` | `https://<PUBLIC_HOST>/attendance/api` |
| `config.prod.js` | 可不生成 | **必须**由 render 生成 |
| 后端启动 | `./start.sh dev` | `./start.sh restart-prod` |
| 开发者工具 | 可勾选「不校验合法域名」 | **必须取消**勾选 |
| 上传发布 | 不需要 | 改配置后**必须**重新上传 |

#### 5.8.9 常见故障（小程序）

| 现象 | 优先检查 |
|------|----------|
| `request:fail network error` | C-1 是否为 `true`；D-2 合法域名；E-2 是否误勾不校验；是否已 E-4 上传新版本 |
| 日志 API 为 `localhost` | C-1、`apiBaseUrlOverride`、是否真机却用本地包 |
| 「飞书凭证未配置」 | B-3/B-4、`secrets.env`、是否 `restart-prod` |
| 授权码成功，登录 500 | B-5 服务器能否访问 `open.feishu.cn`；Nginx 是否转发 `/attendance/api` |
| `[config] config.prod.js 不存在` | 执行 C-2 或 `restart-prod` |

专项排查：[飞书小程序登录问题排查.md](../飞书小程序登录问题排查.md)。

### 5.3 停止服务

```bash
# 查找占用 8080 的进程
lsof -ti :8080 | xargs kill

# 或使用 systemd
sudo systemctl stop attendance-backend
```

### 5.4 使用 systemd（推荐生产）

`/etc/systemd/system/attendance-backend.service`：

```ini
[Unit]
Description=AttendanceAgent Backend
After=network.target mysql.service

[Service]
Type=simple
User=deploy
WorkingDirectory=/opt/AttendanceAgent
Environment=ATTENDANCE_DEPLOY_ENV=production
ExecStart=/opt/AttendanceAgent/scripts/start-backend-prod.sh
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable attendance-backend
sudo systemctl start attendance-backend
sudo systemctl status attendance-backend
```

**改域名后**：`sudo systemctl restart attendance-backend`（启动脚本会重新 render）。

```
deploy/secrets.env（或 backend/.env）
    ↓
deploy/rendered/production.env   ← 覆盖 URL、域名、CORS、SPRING_PROFILES_ACTIVE
```

### 5.6 性能表 `task_records`（B+）

后端启动时会自动：

1. 创建 `task_records` 行级表（见 `backend/config/migration/007_task_records.sql`）
2. 对尚无行级数据的历史任务做一次性回填（日志关键字：`task_records 历史回填完成`）

**日常无需手工跑 SQL。** 识别完成、确认、校准、作废、失败及飞书 `record_id` 回写后会自动同步。

| 现象 | 处理 |
|------|------|
| 考勤记录列表为空但任务详情有数据 | 等待回填完成，或 `./start.sh restart-prod` 触发再次回填 |
| 回填较慢 | 任务量大时首次启动多等 1～2 分钟，看后端日志 |
| 单用户识别报 429 | 同账号并发识别超过 `attendance.recognition.max-per-user`（默认 2），稍后再试 |

可选：手动执行迁移 SQL（与自动建表结构一致）：

```bash
mysql -u root -p attendance_assistant < backend/config/migration/007_task_records.sql
mysql -u root -p attendance_assistant < backend/config/migration/008_task_progress.sql
```

### 5.7 性能终局（Phase 2，已内置）

| 能力 | 说明 |
|------|------|
| `GET /tasks/{id}/progress` | 识别轮询只拉 status/行数/引擎，不拉整段 JSON |
| 识别进度写库 | 平时只更新 `progress_row_count`；每 20 条才写一次全量 `raw_data` |
| 重名检测 | baseline 按当前页 `work_date` + `base_name` 收窄，最多 5000 行 |
| `task_records` | 按 `row_key` upsert + 删除孤儿行，不再全表 delete+insert |
| 慢 SQL / 慢接口 | 日志阈值见 `attendance.performance.*` |
| 对象存储 | `attendance.storage.type=oss` + `OSS_*` 环境变量；默认 `local` |

## 8. 故障排查

### 8.1 后端启动失败

| 错误信息 | 原因 | 处理 |
|----------|------|------|
| `FEISHU_REDIRECT_URI 未设置` | 未走 `start-backend-prod.sh` 或未 render | 使用 `./start.sh restart-prod` |
| `生产环境必须配置 JWT_SECRET` | secrets 缺失或太短 | 检查 `deploy/secrets.env` |
| `Port 8080 was already in use` | 旧进程未退出 | `lsof -ti :8080 \| xargs kill -9` |
| 数据库连接失败 | MySQL 未启动或密码错误 | 检查 `DB_*` 变量 |

### 8.2 飞书登录失败

| 现象 | 排查 |
|------|------|
| PC 飞书登录 500 | 服务器能否访问 `open.feishu.cn`：`curl -I https://open.feishu.cn` |
| 小程序「凭证未配置」 | `readiness` 接口 + `FEISHU_APP_SECRET` |
| 小程序 network error | 是否 `USE_PUBLIC_API=true`；合法域名是否配置 |
| OAuth 回调 404 | Nginx 是否转发 `/attendance/api`；`FEISHU_REDIRECT_URI` 是否与平台一致 |
| 控制台 `Failed to load resource 404` | 见下方 **8.2.1** |

#### 8.2.1 PC 飞书登录控制台 404（常见两条）

| 请求 URL | 原因 | 处理 |
|----------|------|------|
| `/feishu/callback?exchange=...` | 后端仍用旧版前端回调地址（无 `/attendance`） | `git pull` + `./start.sh restart-prod`；或 Nginx 302 到 `/attendance/feishu/callback`（见 `deploy/nginx-production-snippet.conf.example`） |
| `/favicon.ico` | 浏览器自动请求根路径图标 | 可忽略；或 Nginx `return 302 /attendance/favicon.svg` |

**自检（应均为 200）：**

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://uat-guanpei.eminxing.com/attendance/feishu/callback
curl -s -o /dev/null -w "%{http_code}\n" https://uat-guanpei.eminxing.com/attendance/api/config/current-country
```

若第一条 200、浏览器仍打开 `/feishu/callback`，说明 **OAuth 成功页跳转地址未更新**，必须重启生产后端或加 Nginx 兜底。

详细步骤见 [飞书小程序登录问题排查.md](../飞书小程序登录问题排查.md)。

### 8.3 改域名后仍访问旧地址

1. 确认已改 `production.yaml` 而非其他文件
2. 执行 `./start.sh restart-prod`（不是只 kill 再 mvn）
3. 检查 `deploy/rendered/production.env` 中 `PUBLIC_HOST` 是否已更新
4. 飞书开放平台、小程序是否已同步
