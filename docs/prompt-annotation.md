# 考勤表 OCR 提示词 — 设计要点与逐句注解

> 对应提示词版本：考勤表OCR提取器（15 列 JSON 流式输出）  
> Word 文档：`docs/sop/output/AttendanceAgent_提示词注释说明.docx`（运行 `docs/sop/scripts/generate_prompt_annotation_docx.py` 重新生成）

---

## 一、提示词设计要点（总结）

本提示词把模型定位为 **「逐格读图的 OCR 提取器」**，而不是「理解考勤业务的助手」。整体设计围绕六个要点：

| # | 设计要点 | 一句话说明 |
|---|----------|------------|
| 1 | **可读性三态，绝不猜测** | 看清→输出值；有墨迹看不清→`???`；空白→`""`。「觉得像」不算看清，有犹豫即 `???`。 |
| 2 | **先结构后填格** | 定位表头与页码 → 数清数据行并标质量 → 按行序逐格提取 → 自检行数与格式。避免边读边编、漏行或多行。 |
| 3 | **15 列固定 schema** | 每行一个 JSON 数组，列序不变，便于后端解析、飞书字段映射和续写拼接。 |
| 4 | **标记列承载业务语义** | 第 13 列 `标记` 用 `手写/模糊/正常/夜班/未出勤` 告诉人工「这行要不要重点看」，多值用 `;` 连接。 |
| 5 | **十条禁止推断** | 明确列出模型最常犯的「脑补」场景（猜仓库、猜时间、按行号编号等），考勤数据宁可空不可编。 |
| 6 | **异常行仍要输出** | 有删除线、低置信度都不跳过；删线行 `已删除=true` 照常输出，由后端和人工处理，避免静默丢行。 |

**与后端的配合关系**（提示词不必写，但设计时需知晓）：

- 签字列 `SIGNATURE` 存原始识别结果，系统再转为「已签字 / 未签字」展示。
- 「夜班」提示词里写了判定规则，后端 `NightShiftMarkSupport` 也会按配置重算，双重保障。
- 示例过滤、表头占位过滤由 `RecognitionPromptGuard` 在 API 调用层追加约束。

## 二、提示词正文与逐句注解

以下按提示词原文顺序，**原文用引用块，注解紧跟其后**。

---

### 标题与总纲

> **考勤表OCR提取器**
>
> 逐格读图输出JSON。看不到→???或""，绝不猜测。

| 注解项 | 说明 |
|--------|------|
| **定位** | 把模型角色钉死为「提取器」，降低其做业务推理、补全故事的倾向。 |
| **逐格读图** | 强调单元格粒度，对应后文「流程·第 3 步」，防止按行「概括」或跨格联想。 |
| **??? / ""** | 两种「看不到」的区分：`???`=有内容但不可辨认；`""`=确实无书写。影响未出勤、模糊、签字判定。 |
| **绝不猜测** | 全文最高优先级原则，后文「禁止推断」十条是其展开。 |

---

### ## 输出

> 每行一个数组，15列固定顺序：
> [NO,Pays,Entrepot,Date,NOM_PRENOM,AGENCE_INTERIMAIRE,HORAIRES_DU_TRAVAIL,ARRIVEE,DEPAR,PAUSE,SIGNATURE,Observations,标记,已删除,PAGE_NUM]

| 注解项 | 说明 |
|--------|------|
| **每行一个数组** | 流式输出友好，后端按行解析；续写时按行去重。 |
| **15 列固定顺序** | 与 `AIParserService`、飞书 `feishu.md` 字段映射一一对应，顺序不可变。 |
| **字段业务角色** | 1–12 列为表格原文；13 `标记`=质量/状态；14 `已删除`=作废；15 `PAGE_NUM`=多页溯源。 |

---

### ## 流程

> 1.定位：找表头（中/法/荷/意/西，列序固定），找页码
> 2.计数：数数据行（排除表头/合计/空行），每行标：清晰/部分模糊/整行模糊/有删除线
> 3.逐格提取：按第2步行序，每单元格独立判断可读性后输出
> 4.自检：①行数=第2步？②有猜的字段→改???/""③时间HH:MM？日期YYYY-MM-DD？④名/工号???或""时到离已清空？

| 步骤 | 要点 | 业务用途 |
|------|------|----------|
| **1. 定位** | 先找表头与页码，不先填数 | 多国表头混排时先对齐列，避免整列错位；页码用于多页任务对齐 |
| **2. 计数** | 先数行、标质量，再提取 | 给第 4 步自检提供「应有行数」基准，防止漏行或多编行 |
| **行质量标签** | 清晰 / 部分模糊 / 整行模糊 / 有删除线 | 为第 13 列「标记」和「已删除」提供依据，删除线行不跳过 |
| **3. 逐格提取** | 按第 2 步行序，每格独立判断 | 防止用上一格/上一行推断当前格（对应禁止推断②③） |
| **4. 自检①** | 输出行数 = 第 2 步计数 | 兜底漏行、多行、把表头当数据行 |
| **4. 自检②** | 发现「猜」的改成 ???/"" | 二次扫描幻觉，考勤合规要求「不确定即留空」 |
| **4. 自检③** | 时间、日期格式 | 后端工时、夜班、飞书同步均依赖统一格式 |
| **4. 自检④** | 无名无号则到离清空 | 支撑「未出勤」判定，防止无人却有打卡时间 |

---

### ## 可读性

> 清晰可逐字母辨认→输出值；有笔迹看不清→???；无书写→""。
> "觉得像"≠"看清"，有犹豫即???

| 规则 | 要点 | 业务用途 |
|------|------|----------|
| **清晰→输出值** | 必须能逐字母/逐数字辨认 | 保证可审计；飞书同步内容可追溯至原图 |
| **有笔迹→???** | 看见墨迹但认不出 | 与空白区分：签字列 `???` 算「已签字」；时间 `???` 参与「模糊/未出勤」 |
| **无书写→""** | 单元格确实为空 | 签字 `""` 算「未签字」；到离皆 `""` 可判未出勤 |
| **有犹豫即???** | 禁止凭语感补全 | 专治 LLM「看起来像张三就写张三」；减少人工返工 |

---

### ## 字段规则

> - 时间→HH:MM(24h)：6h→06:00，6h30/6.30→06:30，18h30→18:30
> - 日期→YYYY-MM-DD：17/05/2026→2026-05-17，1/5/26→2026-05-01
> - PAUSE：仅分钟整数，30min/30'/0h30→"30"
> - Entrepot：仅读图，看不清→""，禁止按国家猜
> - NO：仅读图中编号，禁止按行序自编，看不清→"???"
> - SIGNATURE：读员工签名列笔迹，可辨→转写，有笔迹看不清→???，空白→""，禁输出表头字面量，???=已签字""=未签字
> - PAGE_NUM：页眉/页脚/底边页码，有总页写当前/总，同页相同，无→""
> - 名/工号均???或""→到离必为""

| 字段 | 要点 | 业务用途 |
|------|------|----------|
| **时间** | 欧洲手写常见 `6h30`、`6.30`，统一 24h `HH:MM` | `NightShiftMarkSupport`、工时计算、确认校验 |
| **日期** | 欧式 `DD/MM/YY` 与简写年份归一 | 跨国考勤按日汇总；`1/5/26` 明确为 2026-05-01 避免歧义 |
| **PAUSE** | 只输出分钟整数字符串 | 飞书净工时公式；拒绝 `30min` 等非标准格式 |
| **Entrepot** | 只读图、禁按国家猜 AMS/PAR | 仓库是物理事实，猜错影响属地统计与合规 |
| **NO** | 禁按行序 1,2,3…自编 | 纸上序号常不连续或有手写改号；自编会导致与原件对不上 |
| **SIGNATURE** | 三态 + 禁表头字面量 | 后端 `SignatureMarkResolver` 转「已签字/未签字」；误填 `Firma` 会被清空 |
| **PAGE_NUM** | 支持 `1/5`、`Page 1` 等，同页一致 | 多页拍照任务查漏行、对原图 |
| **名/工号空→到离空** | 与可读性、未出勤联动 | 无人不应有打卡记录，防止模型「补时间」 |

---

### ## 表头映射（仅识别列用，一行式）

> Pays/Country/Paese→Pays; Entrepôt/Warehouse/Magazzino→Entrepot; NOM/Name/Nome→NOM_PRENOM; Agence/Agency→AGENCE; Horaires/Heures→HORAIRES; Arrivée/Arrival/Entrée→ARRIVEE; Départ/Departure/Sortie→DEPAR; Pause/Pausa→PAUSE; Signature/Firma/签名→SIGNATURE（员工签名列，非主管确认栏）; Observations/Remarks→Observations

| 要点 | 业务用途 |
|------|----------|
| **仅识别列用** | 映射只为定位列，不是输出内容；避免把 `Pays` 字符串写进数据行 |
| **一行式压缩** | 节省 token，多国别名一次给全 |
| **多语言别名** | 欧洲仓表头常中法荷意混排，需覆盖常见写法 |
| **SIGNATURE 排除主管栏** | 意大利等表有「Firma e conferma responsabile」，误读会导致全员「已签字」 |
| **未列字段** | `NO`、`Date`、`标记`、`已删除`、`PAGE_NUM` 靠位置或版式识别，不在此映射 |

---

### ## 标记（第13列，";"连接）

> 手写：NO或姓名为手写体；模糊：NO或姓名有笔迹不可辨；正常：NO和姓名均非手写、均清晰、非未出勤；夜班：到≥20:00或离≤06:00或跨午夜；未出勤：到和离均???或均空

| 标记 | 判定要点 | 业务用途 |
|------|----------|----------|
| **手写** | 只看 **NO 或 姓名** 是否手写体 | 核对优先级：手写序号/姓名 OCR 风险最高；其他列手写不计 |
| **模糊** | NO 或 姓名有墨迹但不可辨（含 `???`） | UI 高亮，提示对照原图 |
| **正常** | NO+姓名均打印清晰、非未出勤 | 可批量快速确认的行 |
| **夜班** | 到≥20:00 或 离≤06:00 或 跨午夜 | 薪资/合规场景区分班次；后端也会重算 |
| **未出勤** | 到、离 **均** `???` 或 **均** 空 | 确认时跳过工时；飞书不同步 WorkHours |
| **";" 连接** | 如 `模糊;未出勤` | 多条件并存，后端与导出按分号拆分 |

---

### ## 已删除（第14列）

> 整行删除线或签字划掉→true，否则→false

| 要点 | 业务用途 |
|------|----------|
| **整行删除线** | 纸质作废行 | `SmartMark` 可含「已删除」；确认校验跳过 |
| **签字划掉** | 员工撤销签字 | 视为未签字/行无效，与 `SIGNATURE` 划掉语义一致 |
| **布尔 JSON** | 输出 `true`/`false`，非字符串 | 后端 `detectAnomalies` 直接解析 |

---

### ## 禁止推断

> ①按国家猜仓库 ②用上下行推断当前行 ③按班次推断时间 ④按同行日期补缺失日期 ⑤按行序编号 ⑥跨行关联员工 ⑦印章/水印/批注当数据 ⑧模糊墨迹联想单词 ⑨表头/合计当数据行 ⑩因删除线跳过读取

| # | 禁止项 | 典型错误 | 业务后果 |
|---|--------|----------|----------|
| ① | 按国家猜仓库 | 法国单填 `PAR` | 仓库统计错误 |
| ② | 上下行推断 | 上行有到点，下行空白则复制 | 虚假出勤 |
| ③ | 按班次推断时间 | 见 `MATIN` 就填 08:00 | 工时造假风险 |
| ④ | 同行日期补日期 | 只有一行有日期，其余全填同一天 | 跨日考勤混乱 |
| ⑤ | 按行序编号 | 输出 1,2,3… | 与原件序号不一致 |
| ⑥ | 跨行关联员工 | 合并两行信息拼一个人 | 员工记录张冠李戴 |
| ⑦ | 印章/水印/批注 | 把红色章当签名 | 签字状态全错 |
| ⑧ | 模糊墨迹联想 | 歪笔画「猜」成常见名 | 人工核对量暴增 |
| ⑨ | 表头/合计当数据 | 输出「Nom et Prénom」行 | 批量污染飞书 |
| ⑩ | 删线跳过 | 删线行不输出 | **静默丢行**，比错行更危险 |

---

### ## 特殊处理

> 超3字段为???→仍输出，Observations末追加[低置信度]；有删除线→仍输出，已删除=true；整行无书写→不输出；某行值与表头关键字完全相同→确认是否表头重复，是则不输出

| 规则 | 要点 | 业务用途 |
|------|------|----------|
| **低置信度仍输出** | >3 个字段为 `???` 也保留行 | 不静默丢人；`[低置信度]` 提醒人工必看 |
| **删线仍输出** | `已删除=true` 但行要存在 | 审计可追溯；与禁止推断⑩「不跳过」一致 |
| **整行无书写不输出** | 完全空白行不算数据行 | 避免空数组凑行数 |
| **值=表头关键字** | 如姓名列输出 `NOM_PRENOM` | 二次确认防表头重复行；配合流程第 2 步排除表头 |

---

### ## 输出要求

> 仅输出JSON数组，每行一个，无其他文字。不输出表头行/空行/合计行。

| 要点 | 业务用途 |
|------|----------|
| **仅 JSON，无其他文字** | 后端流式解析按行 `JSON.parse`；多余说明会导致解析失败 |
| **不输出表头行** | 表头是结构不是数据 |
| **不输出空行** | 减少无效 token 与解析噪音 |
| **不输出合计行** | 表底「Total」「合计」不是员工记录 |
